# harulog

> 하루 기록 앱 — 프론트엔드 개발자가 백엔드를 배우며 8주간 키운 서비스

## 소개

`harulog`는 하루의 기록을 남기고, 태그를 달고, 다른 사람을 팔로우하며 좋아요를 남길 수 있는 개인 기록 서비스입니다.
프론트엔드 개발자가 백엔드 전반(API 설계, DB 설계, 인증/인가, 트랜잭션, 성능, 배포)을 익히기 위해 8주 동안 기능을 하나씩 쌓아가며 만들었습니다.

## 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 언어 | Python 3.12 |
| 웹 프레임워크 | FastAPI |
| DB | PostgreSQL 16 |
| ORM / 마이그레이션 | SQLAlchemy + Alembic |
| 캐시 | Redis |
| 실행 환경 | Docker Compose |
| 테스트 | pytest |

## 프론트엔드와 백엔드, 무엇이 다른가

| | 프론트엔드 | 백엔드 |
|---|---|---|
| 누가 쓰나 | 브라우저 1개 = 사람 1명 | 서버 1대 = 사람 수천 명 |
| 데이터 | 새로고침하면 사라짐 | 사라지면 안 됨 |
| 동시 실행 | 거의 신경 안 씀 | 같은 코드가 동시에 100번 돌아감 |
| 잘못되면 | 화면이 깨짐 | 데이터가 깨짐 (못 되돌림) |
| 배포 | 파일만 바꾸면 끝 | DB 구조도 같이 바뀜 |

## 주요 기능

- 회원가입 / 로그인 / 토큰 재발급 / 로그아웃
- 하루 기록 작성·수정·삭제·조회 (공개 / 비공개)
- 기록에 태그 달기
- 기록에 사진 업로드 (최대 5장)
- 팔로우 / 팔로우한 사람 글 목록
- 좋아요
- 가입 확인 메일 발송
- 소프트 삭제 + 감사 로그(audit log)

## 폴더 구조

```
app/
├── main.py          앱 조립. 로직 안 씀
├── core/            설정, 에러, 보안 도구, 로그
├── api/v1/          요청 받고 응답 돌려주기만
├── schemas/         입력·출력 형식 (프론트와의 약속)
├── models/          DB 표 구조
├── repositories/    조회·저장. 트랜잭션은 안 엶
├── services/        실제 처리 로직 + 트랜잭션. HTTP를 모름
├── infra/           밖과 연결 (메일, 파일 저장소, 결제)
└── workers/         뒤에서 도는 작업. services를 그대로 재사용
tests/
```

호출 방향은 한 쪽으로만: `api → services → repositories → models`, `services → infra`

## 실행 방법

```bash
# 패키지 설치
uv sync

# DB + Redis 실행
docker compose up -d

# 마이그레이션 적용
uv run alembic upgrade head

# 서버 실행
uv run uvicorn app.main:app --reload
```

- API 문서: `http://localhost:8000/docs`
- 헬스체크: `http://localhost:8000/health`

## 테스트

```bash
uv run pytest
```

## 8주 학습 로드맵

| 주차 | 주제 | 결과물 |
|---|---|---|
| 0 | 준비하기 | 개발 환경 |
| 1 | 서버 기본 틀 만들기 | 동작하는 API |
| 2 | DB 다루기 (SQL 먼저) | 관계도 + SQL로 만든 기능 |
| 3 | ORM·연결·트랜잭션 | ORM 전환 + 마이그레이션 |
| 4 | 로그인·권한·보안 | 로그인 + 보안 점검표 |
| 5 | 메일·파일·느린 작업 | 메일 + 사진 업로드 |
| 6 | 속도·동시성 | 속도 비교 + 부하 테스트 결과 |
| 7 | 에러·로그·테스트 | 에러 형식 통일 + CI |
| 8 | 배포·운영 | 무중단 배포 + 모니터링 |

각 주차의 자세한 할 일과 완료 기준은 [`backend-todo.md`](./backend-todo.md)에 정리되어 있습니다.
